# 架构说明（obstrans）

> 本文档从华为云视角描述 `obstrans` 对象存储断点续传工具的架构与工作原理。

## 1. 总体架构

`obstrans` 是一个基于华为云对象存储服务（OBS）的命令行工具，提供大文件多段上传、分段下载、桶间迁移与基于消息队列的分布式集群传输能力。整体由「CLI 调度层 + OBS SDK 适配层 + 可选的消息队列编排层」构成。

```
┌──────────────────────────────────────────────────────────────────────┐
│                         obstrans CLI                                 │
│                                                                      │
│  ┌───────────┐  ┌───────────┐  ┌───────────┐  ┌──────────────────┐  │
│  │  上传模式  │  │  下载模式  │  │  桶间迁移  │  │  HTTP 预签名下载  │  │
│  │ (多段上传) │  │ (分段下载) │  │ (OBS→OBS) │  │  (断点续传下载)   │  │
│  └─────┬─────┘  └─────┬─────┘  └─────┬─────┘  └────────┬─────────┘  │
│        └───────────────┴───────────────┴─────────────────┘            │
│                              │                                        │
│                    ┌─────────▼──────────┐                             │
│                    │   OBS SDK (Go)     │                             │
│                    │   多段上传 / 列表   │                             │
│                    └─────────┬──────────┘                             │
│                              │                                        │
│              ┌───────────────┼────────────────┐                     │
│              ▼               ▼                ▼                     │
│        ┌──────────┐   ┌──────────┐    ┌──────────────┐              │
│        │  源桶     │   │  目标桶   │    │ DMS Kafka   │              │
│        │ (OBS)    │   │ (OBS)    │    │ (集群模式)   │              │
│        └──────────┘   └──────────┘    └──────────────┘              │
└──────────────────────────────────────────────────────────────────────┘
```

**核心组件**

| 组件 | 职责 |
|------|------|
| obstrans CLI | 解析命令行参数、编排上传/下载/迁移/校验等工作模式 |
| OBS SDK（Go） | 调用华为云 OBS 多段上传 / 分段下载 / 服务端拷贝 / 对象列举接口 |
| OBS 源桶 / 目标桶 | 实际存储对象数据的对象存储服务桶 |
| DMS Kafka（可选） | 集群模式下作为任务队列，编排多节点并行传输 |

## 2. 工作模式

| 模式 | 说明 |
|------|------|
| `UPLOAD` | 将本地文件多段上传至 OBS 桶 |
| `DOWNLOAD` | 从 OBS 桶分段下载到本地 |
| `COPY` | 在两个 OBS 桶之间迁移对象（服务端拷贝，不经本地磁盘） |
| `DRYRUN` | 仅列举与对比两端对象，不执行实际传输 |
| `CHECK` | 校验源端与目标端对象的一致性（MD5） |
| `DMS_SEND` / `DMS_CONSUME` | 集群模式：向 Kafka 投递任务 / 从 Kafka 消费任务执行传输 |

## 3. 断点续传机制

- **上传**：使用 OBS 多段上传接口，记录已上传的段号与 UploadId；中断后通过列举已上传段跳过已完成部分。
- **下载**：使用 HTTP Range 请求分段下载，记录已完成段的偏移量；中断后仅补全缺失段。
- **进度记录**：本地维护进度文件（`<key>.obstmp`），重启时检测既有进度，避免重复传输。

## 4. 多段上传流程

1. **初始化多段上传**：调用 `InitiateMultipartUpload` 获取 UploadId。
2. **逐段上传**：按 `--part-size` 将文件切片，并发调用 `UploadPart`。
3. **完成上传**：调用 `CompleteMultipartUpload` 合并所有段。

## 5. 桶间迁移

`COPY` 模式直接在 OBS 服务端完成桶间拷贝，数据不经过本地磁盘，适合大规模数据搬迁；`DRYRUN` 用于迁移前的容量评估与差异分析，`CHECK` 用于传输后的一致性校验。

## 6. 分布式集群模式

集群模式使用 DMS Kafka 作为任务队列：发送端将对象列表发布到 Topic，多个消费端节点组成消费组并行执行传输任务，Kafka 自动做负载均衡。增加消费端节点即可线性提升吞吐量。

```
                    ┌───────────────┐
                    │  DMS Kafka    │
                    │    Topic      │
                    └───┬───────┬───┘
                        │       │
              ┌─────────▼─┐   ┌─▼─────────┐
              │ Worker 1  │   │ Worker 2  │  ... N 个 Worker
              └─────┬─────┘   └─────┬─────┘
                    │               │
              ┌─────▼─────┐   ┌─────▼─────┐
              │ 源 OBS 桶 │   │ 目标OBS桶 │
              └───────────┘   └───────────┘
```

## 7. HTTP 预签名下载

支持通过 HTTP 预签名 URL 从外部源下载文件至 OBS 桶，下载过程支持 HTTP Range 请求，可分段并发拉取。

## 8. 安全设计

- AK/SK 仅通过环境变量 `HW_ACCESS_KEY` / `HW_SECRET_KEY` 注入，不落盘。
- DMS Kafka 使用 SASL_SSL 加密传输。
- OBS 桶默认 ACL 为 `private`。
- 所有传输均使用 HTTPS。
